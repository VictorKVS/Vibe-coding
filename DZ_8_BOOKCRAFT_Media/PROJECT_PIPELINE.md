# BOOK.CRAFT · Author Project Pipeline

## Цель

Проект пользователя становится контейнером произведения и всех производных материалов. Автор сначала входит в локальное рабочее пространство, затем выбирает проект и работает внутри него.

## Этапы проекта

`Источник → Разбор → По мотивам → Комикс → Видео`

### 1. Источник

Поддерживаемые входы следующего этапа:

- локальный TXT / MD / DOCX / PDF / EPUB;
- рассказ или книга целиком;
- URL страницы/произведения с явным действием пользователя «Импортировать»;
- несколько источников внутри одного проекта.

Для каждого источника хранить происхождение, название, дату импорта, тип, контрольную сумму и статус обработки.

### 2. Разбор

Книга/сборник раскладывается на структурные узлы:

- произведение;
- главы/части;
- рассказы внутри сборника;
- сцены/эпизоды;
- персонажи;
- места;
- события;
- временная линия;
- связи персонажей;
- словарь сущностей и понятий.

Оригинальный текст хранится отдельно от машинных выводов. Любое машинное извлечение имеет ссылку на источник и диапазон/чанк.

### 3. По мотивам

Создание новых материалов выполняется как отдельная производная ветка проекта. Нужно хранить:

- исходный канон;
- пользовательскую инструкцию;
- новые события;
- заимствованные факты мира;
- отличия от исходника;
- версии и историю генераций.

### 4. Комикс

Для сцен формируется storyboard:

- кадры;
- герои и постоянство внешности;
- композиция;
- арт-промпты;
- изображения и версии;
- реплики/подписи;
- связь каждого кадра с текстовой сценой.

### 5. Видео

На основе storyboard:

- план сцен;
- длительности;
- изображения/видеофрагменты;
- озвучка;
- музыка/эффекты;
- субтитры;
- монтажная последовательность;
- экспорт готового ролика.

## Хранение

`localStorage` используется только для лёгких настроек, author session marker и текущих UI snapshot.

Большие книги, изображения, embeddings, чанки и производные материалы должны перейти в локальное проектное хранилище: backend + SQLite/файловый workspace; векторный индекс подключается отдельно для поиска по памяти проекта.

## Трассировка

Каждый этап обязан следовать `TRACEABILITY_STANDARD.md`:

- импорт;
- парсинг;
- чанкинг;
- извлечение сущностей;
- генерация;
- выбор модели;
- fallback;
- создание изображения/видео;
- сборка/экспорт.

Для каждой долгой операции UI показывает прогресс и correlation/request id.

## Ближайшие итерации

1. Author login + project list + migration существующего проекта.
2. Локальное project storage API вместо хранения больших данных в браузере.
3. Import Center: файл + URL.
4. Document/Book Parser и дерево произведения.
5. Project Memory / retrieval.
6. Inspired-work branch/versioning.
7. Comic storyboard pipeline.
8. Video pipeline.
