# AI-секретарь — профессиональный Telegram UX

## Общие правила

1. Все визуалы — в едином корпоративном стиле: тёмно-синий/графитовый фон, белый текст, бирюзово-голубые AI-акценты.
2. На изображениях не рисуем Telegram-кнопки. Все кнопки — реальные InlineKeyboard/ReplyKeyboard.
3. Картинки используются только как визуальные состояния процесса. Текст критичных событий отправляется отдельным сообщением.
4. Сообщение `Транскрибация завершена успешно.` всегда отправляется отдельно после сохранения `.txt` и только один раз для каждой успешно обработанной записи.
5. Не показываем фиктивный процент. Шкала прогресса обновляется только после завершения реального этапа обработки.
6. Одно служебное сообщение прогресса редактируется через `edit_text()`; не создаём новое сообщение на каждом шаге.
7. При ошибке прогресс заменяется на понятное сообщение с этапом, где произошёл сбой.
8. После завершения доступны PDF и режим вопросов по транскрипту.

## Реальная шкала прогресса

Сопоставление процентов с фактически завершёнными этапами:

- 0% — файл принят;
- 15% — файл скачан/получен по ссылке;
- 30% — аудиодорожка подготовлена через ffmpeg;
- 60% — AssemblyAI завершил транскрибацию;
- 70% — транскрипт сохранён в `transcripts/*.txt`;
- 85% — AI сформировал саммари, задачи и ответственных;
- 92% — данные записаны в Google Sheets (либо зафиксирована понятная ошибка записи);
- 100% — PDF-протокол сформирован и доступен пользователю.

Пример одного редактируемого сообщения:

```text
Обработка встречи
██████░░░░ 60%
Транскрибация завершена
```

Это не таймер: процент меняется только при реальном завершении соответствующей операции.

## Полный сценарий диалога

### SCR-001 — `SCR-001_secretary_start.jpg`

**Событие:** `/start`

Текст:

```text
AI-СЕКРЕТАРЬ ВСТРЕЧ

Превращаю аудио и видео встреч в структурированный протокол.

Пришлите:
• аудиофайл;
• видеофайл;
• голосовое сообщение;
• ссылку Google Drive / прямую ссылку на запись.
```

Кнопки:

- `📎 Как отправить запись`
- `ℹ️ Возможности`

### SCR-002 — `SCR-002_file_received.jpg`

**Событие:** пользователь прислал медиа или URL.

Отдельный текст:

```text
Файл получил ✅ Сейчас обработаю.
```

После него создаётся одно сообщение прогресса:

```text
Обработка встречи
█░░░░░░░░░ 0%
Файл принят
```

Кнопка во время обработки:

- `✖️ Отменить обработку` — только если реализована безопасная отмена текущей задачи; иначе кнопку не показывать.

### SCR-003 — `SCR-003_transcription.jpg`

Изображение отправляется один раз при входе в этап транскрибации.

Прогресс обновляется:

```text
Обработка встречи
███░░░░░░░ 30%
Аудио подготовлено. Выполняю транскрибацию…
```

После ответа AssemblyAI и сохранения `.txt` обязательно отдельное сообщение:

```text
Транскрибация завершена успешно.
```

После него прогресс:

```text
Обработка встречи
███████░░░ 70%
Текст получен и сохранён
```

### SCR-004 — `SCR-004_analysis.jpg`

Текст этапа:

```text
AI анализирует встречу…
Выделяю основные темы, задачи, ответственных и дату следующей встречи.
```

Прогресс после анализа:

```text
Обработка встречи
████████▌░ 85%
Саммари и задачи готовы
```

После успешной записи Sheets:

```text
Обработка встречи
█████████░ 92%
Данные сохранены в Google Sheets
```

Если Google Sheets недоступен:

```text
Не удалось записать данные в Google Sheets.
Проверьте доступ сервисного аккаунта к таблице.
```

При этом бот не должен терять транскрипт и результаты анализа и может продолжить формирование PDF.

### SCR-005 — `SCR-005_protocol_ready.jpg`

После формирования PDF прогресс редактируется в финальный вид:

```text
Обработка встречи
██████████ 100%
Готово ✅
```

Затем отдельное сообщение:

```text
Протокол встречи готов.
Данные встречи обработаны, а PDF можно скачать ниже.
```

Кнопки:

- `📄 Скачать протокол PDF`
- `💬 Задать вопрос по встрече`
- `🔄 Обработать новую запись`

### SCR-006 — `SCR-006_ask_ai.jpg`

**Событие:** пользователь нажал `💬 Задать вопрос по встрече` или просто пишет текст после успешной обработки.

Текст:

```text
Режим вопросов по встрече активирован.
Я отвечаю только на основании последнего сохранённого транскрипта.
```

Пример:

Пользователь: `Кто отвечает за подготовку презентации?`

Бот: `За подготовку презентации отвечает Андрей.`

Если информации нет:

```text
В записи это не обсуждалось.
```

Кнопки:

- `📄 Скачать PDF`
- `🔄 Новая запись`
- `🏠 Главное меню`

## Поведение при больших файлах

Если стандартный Telegram Bot API не позволяет скачать файл:

```text
Файл слишком большой для скачивания через стандартный Telegram Bot API.
Пришлите публичную ссылку Google Drive или прямую ссылку на файл — я продолжу обработку.
```

При получении ссылки:

```text
Ссылку получил ✅ Сейчас обработаю.
```

Далее используется тот же прогресс и тот же сценарий без отдельной ветки интерфейса.

## Ошибки

Ошибки должны быть пользовательскими, а не техническими.

Не показывать:

```text
KeyError
HTTPError
Traceback
```

Показывать:

```text
Не удалось сформировать PDF. Транскрипт и результаты анализа сохранены. Попробуйте повторить создание протокола.
```

или:

```text
Сервис транскрибации временно недоступен. Попробуйте повторить обработку позже.
```

Технический traceback печатается только в лог Colab.

## Главный UX-принцип

Картинка объясняет состояние визуально. Реальный Telegram-текст сообщает факт. Кнопка предлагает следующее действие. Прогресс показывает только реально завершённые этапы.
