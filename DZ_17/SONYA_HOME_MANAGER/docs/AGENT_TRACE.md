# SONYA Agent Trace

## Назначение

`Agent Trace` показывает пользователю и разработчику реальную последовательность технических действий во время мультимодального анализа.

Это **операционная трассировка**, а не вывод скрытых внутренних рассуждений модели.

## Поток

```text
Пользователь нажал «Анализировать»
        ↓
01 Подготовка изображения
        ↓
02 Сбор пользовательского контекста
        ↓
03 Передача задачи локальному агенту
        ↓
04 Проверка входных данных
        ↓
05 Сбор контекста задачи
        ↓
06 Выбор мультимодальной модели
        ↓
07 Vision inference в Ollama
        ↓
08 Разбор структурированного ответа
        ↓
09 Завершение агентного прохода
        ↓
10 Передача результата в интерфейс
```

## Статусы

- `WAIT` — этап ещё не выполняется;
- `RUN` — этап выполняется сейчас;
- `OK` — этап завершён;
- `ERR` — на этапе произошла ошибка.

Для завершённых этапов интерфейс показывает фактическую длительность в миллисекундах, когда она доступна.

## Request ID

Каждый запуск анализа получает отдельный `requestId`.

Он используется для связи:

```text
Browser
  ↓ requestId
POST /api/analyze
  ↓
Local Agent API
  ↓
Ollama / llava:7b

Browser
  ↕
GET /api/trace?requestId=...
```

Пока основной POST выполняется, frontend опрашивает `/api/trace` примерно раз в 450 мс и обновляет экранный таймлайн.

## Backend trace

Локальный сервер хранит краткоживущую трассу текущих запросов в памяти процесса.

Фиксируются:

- проверка входных данных;
- сбор профиля и режима;
- выбранная vision-модель;
- адрес Ollama;
- начало и окончание inference;
- разбор JSON;
- завершение прохода;
- ошибка, если этап завершился неуспешно.

## Frontend trace

Frontend отдельно фиксирует:

- подготовку/масштабирование фотографии;
- итоговый размер изображения;
- сбор пользовательского контекста;
- отправку запроса;
- получение ответа;
- передачу результата в UI.

## Что НЕ показывается

В трассу не выводятся:

- скрытая chain-of-thought модели;
- внутренние токены рассуждения;
- пароли, ключи или другие секреты;
- полный system prompt;
- необработанные персональные данные.

## UI

Панель `AGENT TRACE` расположена поверх рабочего интерфейса и может быть свёрнута.

На мобильном экране она располагается над нижней навигацией.

Панель остаётся видимой и при ошибке анализа, поэтому по ней можно определить последний успешно выполненный этап.

## Следующий уровень

План развития:

- экспорт trace в JSON;
- журнал последних N запусков;
- фильтр `client / backend / model`;
- throughput и latency statistics;
- trace-id в production;
- OpenTelemetry-совместимый экспорт;
- граф узлов агента вместо только линейного таймлайна.
