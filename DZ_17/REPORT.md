## Как была выстроена логика взаимодействия в сценарии?

Я развил существующий проект **ALINA — AI-продюсер идей** до мультимодального сценария. Пользователь вводит творческую задачу и загружает визуальный референс. Сначала ALINA выделяет только наблюдаемые признаки изображения, затем отдельно интерпретирует их в контексте пользовательской идеи и предлагает три разных направления развития с сильной стороной и возможным риском каждого варианта. Ключевое творческое решение остаётся за пользователем: после предложения вариантов агент ждёт подтверждения и только затем продолжает работу.

Логика:

```text
TEXT + IMAGE
→ OBSERVATION
→ INTERPRETATION
→ 3 PROPOSALS
→ HUMAN CONFIRMATION
→ NEXT STEP
```

Такой подход позволяет использовать мультимодальность не как отдельную функцию «описать картинку», а как часть производственного процесса творческого проекта.

## С какими основными сложностями пришлось столкнуться при генерации стабильного и предсказуемого интерфейса? Как они были решены?

Главная сложность — добиться предсказуемого разделения между **тем, что модель действительно наблюдает на изображении**, и **творческой интерпретацией ALINA**. Без специальных правил модель может сразу переходить к домыслам, продолжать сюжет или представлять интерпретацию как факт.

Для решения был введён структурированный System Prompt и фиксированный порядок ответа:

```text
OBSERVATION
→ CONTEXTUAL INTERPRETATION
→ PROPOSALS
→ AUTHOR DECISION
```

Дополнительно агенту запрещено самостоятельно утверждать творческую интерпретацию как канон проекта и продолжать ключевую сюжетную развилку до подтверждения пользователя. Интерфейс разделяет входные данные, визуальный референс и результат анализа на самостоятельные блоки, что делает поведение приложения понятнее и стабильнее.

# Расширение сверх минимального задания

ДЗ-17 является этапом развития ALINA/WILD_IDEAS, поэтому архитектура предусматривает дальнейшее использование визуальных данных для:

- Character Visual Identity;
- постоянства внешности героя;
- контроля одежды и реквизита по сценам;
- storyboard;
- генерации последовательности кадров;
- анимированных мини-сцен;
- будущего голосового взаимодействия;
- Narrative Knowledge Base и Project Memory.

Эти возможности не подменяют обязательные требования ДЗ-17. Для сдачи отдельно фиксируется минимальный работоспособный сценарий `изображение + текст → мультимодальный ответ`.
