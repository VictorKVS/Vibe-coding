## Голос и Telegram

**[Запуск распознавания и настройка Telegram](VOICE_TELEGRAM.md)**. Микрофон и аудиофайлы распознаются настоящим локальным Whisper; затем Алина отвечает по демонстрационному сценарию. Подготовлены три синтезированные аудиозаписи и результаты их реального распознавания. Адаптер отдельного Telegram-бота готов к настройке токена и разрешённого чата; настоящий обмен с Telegram пока не проверен.

## Бот в центре процесса

Клиент обращается → бот выбирает сценарий → уточняет товар или услугу → получает подтверждение → создаёт заявку в CRM. История клиента, каталог, ответственный и следующий шаг доступны в одном пространстве.

| Профиль | Сценарий | Данные |
|---|---|---|
| Продажи и торговля | Выбор товара и оформление заказа | Каталог, количество, остаток, контакт |
| Клиника | Заявка на приём | Услуга, время, контакт; без медицинских рекомендаций |
| Спорткомплекс | Запись на занятие | Тренировка, время, контакт |
| Автосервис | Заявка мастеру | Вид работ, время, контакт |
| Массажный салон | Запись на сеанс | Процедура, время, контакт |
| Склад и опт | Заявка на поставку | Позиция, количество, остаток, контакт |

Профили хранятся отдельно. Дашборд рассчитывает показатели из текущих заявок за 7 или 30 дней; сумма заявок не выдаётся за оплаченную выручку. Этапы воронки можно менять, каталог использовать в диалоге, данные экспортировать в CSV.

## Виртуальный секретарь

![Тестовый диалог и секретарь Алина](screenshots/02-secretary.png)

Алина — вымышленный взрослый персонаж с улыбкой, морганием и лёгким движением при речи. «Послушать» воспроизводит приветствие, «Озвучивать ответы» включает чтение ответов голосом браузера. В проверке на Windows запустился Microsoft Irina. Наличие русского голоса зависит от браузера и системы; точного совпадения движения губ с речью нет.

## История ваших обращений

![Личная история и три результата](screenshots/03-personal-history.png)

В каждом профиле подготовлены три учебных обращения Виктора: телефон, Telegram и email. Они связаны с карточкой демо-клиента и разными товарами или услугами. Это вымышленные примеры для проверки интерфейса, не реальные звонки, медицинские посещения или покупки.

История хранит три последних разбора. Карточка содержит заголовок, время и текст. Нажатие открывает сохранённый результат со статусом «Готово», без повторного разбора. Четвёртый результат вытесняет старейший. Очистка ввода сохраняет диалоги и историю.

## Запуск на компьютере

Нужен Node.js 22 или новее. Открыть `START_CRM.cmd` либо выполнить:

```sh
node server.cjs
```

Адрес: http://127.0.0.1:5179. Зависимости для запуска не нужны. Предыдущая версия экрана обращений сохранена в `inbox.html`; данные той версии используют отдельный ключ хранения.

Для проверок:

```sh
npm ci
npm test
npm run test:ui
```

Статическая сборка для хостинга:

```sh
node build-static.cjs
```

## Что работает и что ещё подключать

Работают локальный движок сценариев, заявки, профили, история, карточки клиентов, каталог, резерв демо-остатков, воронка, поиск, CSV, настройки приветствия и цели, ошибки, отмена, озвучивание и анимация персонажа.

**Пока не подключены:** LLM, живые телефонные звонки, остальные мессенджеры, серверная многопользовательская база, авторизация, платёжные системы и календарь организации. Локальное распознавание Whisper работает; Telegram-адаптер требует вашего токена и проверки в отдельном боте. Выбор канала в симуляторе только помечает диалог. Запись на услугу создаёт заявку на согласование, а не бронирует реальный слот. В текстовом прототипе используются правила и кнопки; свободное понимание намерений моделью — следующий этап.

Данные находятся в localStorage текущего браузера. Контакты связываются по точному значению без учёта регистра. Для работы с реальными клиентами нужны проверка личности, серверные права доступа и подтверждение связи контактов разных каналов. Учебная история явно выделена.

## Устройство ядра

- `core.mjs` — профили, каталог, переходы диалога, создание заявки, метрики, примеры и разборы.
- `console.mjs` — страницы CRM, локальное хранение, симулятор и озвучивание.
- `index.html`, `console.css` — адаптивный интерфейс и анимация.
- `core.test.mjs`, `ui.test.cjs` — проверки сценариев и поведения интерфейса.
- `build-static.cjs` — публикация статических файлов без серверных ключей.

Следующий слой: адаптеры каналов → STT → LLM для понимания запроса → проверенные действия ядра → интеграция CRM/ERP/календаря. Модель не должна сама выдумывать цену, наличие или подтверждение записи.

## Дизайн и учебный статус

Структура дашборда и воронки ориентирована на привычные подходы [HubSpot](https://www.hubspot.com/products/reporting-dashboards) и [Pipedrive](https://www.pipedrive.com/en/features/sales-dashboard), с собственной визуальной системой BOOKCRAFT ONE.

Это MVP интерфейса и сценарного ядра для ДЗ-9. Для окончательной сдачи по исходному PRO-заданию ещё требуется видео переключения трёх результатов; соответствие сценарного разбора требованиям преподавателя нужно отличать от LLM-анализа качества звонка на Google или Яндекс Диске. Подробный сценарий и границы доказательств — в [ACCEPTANCE.md](ACCEPTANCE.md).
