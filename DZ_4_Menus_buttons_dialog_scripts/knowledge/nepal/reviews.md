# Nepal reviews — analysis layer for Travel Expert AI

> Важное правило: этот файл не содержит выдуманных пользовательских отзывов. Он описывает, как агент должен анализировать реальные отзывы после их загрузки из разрешённых публичных источников или из CRM компании.

## Цель
Travel Expert AI должен уметь отвечать не «отель хороший/плохой», а давать структурированный итог по набору отзывов.

## Что извлекаем из каждого отзыва
- источник и URL;
- дата публикации;
- объект: страна / маршрут / отель / экскурсия;
- рейтинг, если он есть;
- язык;
- положительные темы;
- отрицательные темы;
- упоминания детей;
- упоминания питания;
- упоминания чистоты;
- упоминания персонала;
- транспорт / логистика;
- шум;
- интернет;
- соотношение цена/качество;
- подозрение на дубликат или рекламный текст.

## Итог аналитики
Агент формирует:
1. число проанализированных отзывов;
2. период отзывов;
3. повторяющиеся плюсы;
4. повторяющиеся минусы;
5. редкие, но серьёзные жалобы;
6. отличия отзывов семей, пар и одиночных туристов, если данные позволяют;
7. уровень уверенности;
8. ссылки на использованные источники.

## Ограничения
- один отзыв не считается тенденцией;
- блогерское мнение маркируется как мнение;
- рекламный материал туроператора не смешивается с независимым отзывом;
- нельзя придумывать проценты без фактического количества документов;
- нельзя цитировать автора как доказательство объективного факта;
- старые отзывы должны иметь меньший вес для быстро меняющихся характеристик отеля;
- при недостатке данных агент прямо пишет, что выборка мала.

## Пример формата ответа
«В базе 24 отзыва за последние 12 месяцев. Чаще всего хвалят расположение и работу персонала. Повторяющаяся претензия — шумоизоляция (6 отзывов). Данных недостаточно, чтобы уверенно оценить качество Wi‑Fi: оно упоминается только дважды.»

Этот пример демонстрирует формат и не относится к конкретному отелю.

## Хранение сырья
Реальные отзывы для MVP складываются отдельно, например:
`knowledge/nepal/research/reviews.jsonl`.

Поля записи:
`source_url`, `source_type`, `published_at`, `collected_at`, `object_id`, `rating`, `text`, `language`, `status`.

В RAG допускаются только записи со статусом `approved` или аналитическое резюме, построенное из них.
