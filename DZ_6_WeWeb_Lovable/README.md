# BOOK·CRAFT — DZ-6

## Онлайн-витрина

Публичная версия для просмотра и сдачи:  
**https://victorkvs.github.io/Vibe-coding/**

GitHub Pages автоматически пересобирает витрину после изменений в папке
`DZ_6_WeWeb_Lovable`. Интерфейс, dropdown, демо, ручное редактирование,
автосохранение и импорт/экспорт работают в браузере. Локальная генерация
GigaChat запускается через `START_BOOK_STUDIO.cmd`, потому что браузерная
витрина не имеет доступа к модели на домашнем компьютере.

## Сдаваемый MVP

MVP завершён: проект автоматически сохраняет жанр, три части сценария, историю
чата, режим источников, базу знаний и паспорта персонажей. После обновления
страницы работа восстанавливается автоматически. Кнопки «Экспорт» и «Импорт»
создают переносимую JSON-копию проекта и загружают её обратно. API-ключи и
временный токен GigaChat в автосохранение и экспорт не входят.

## Универсальный модельный агент

В интерфейс добавлен Model Gateway. BOOK·CRAFT больше не ограничен одной
моделью: можно выбрать подтверждённую локальную LLM либо указать внешний агент,
OpenAI-compatible endpoint, model ID и API-ключ, проверить подключение и затем
тестировать разные модели на одном сценарии.

Локальный dropdown ограничен моделями, которые ранее были обнаружены у владельца
в LM Studio. Ключ внешнего агента существует только в памяти открытой вкладки:
он не записывается в localStorage, проект, экспорт или GitHub. Для публичного
развёртывания требуется серверное секрет-хранилище/proxy.

Учебное приложение для создания сценариев книг и видеороликов с локальным
GigaChat. Проект выполняет обязательное требование DZ-6: dropdown из пяти
жанров, хранение выбранного жанра в state и явное отображение текущего значения.

Дополнительно реализована локальная база знаний: пользователь добавляет
TXT/MD/JSON и выбирает режим «Оригинальная история», «По мотивам» или
«Продолжение». На уровне MVP содержимое источников хранится только в браузере и
передаётся локальному GigaChat вместе с запросом.

Текстовая генерация защищена от типового сбоя локальной модели: запрос имеет
тайм-аут 90 секунд, ответ проверяется на четыре обязательных строковых поля. Если
GigaChat добавил пояснения или сломал JSON, приложение один раз автоматически
исправляет только формат. При повторной ошибке текущий сценарий не затирается.

Визуальная система рассчитана на творческую аудиторию: анимированные цветовые
переливы, световые дорожки по краям карточек, искры, мягкое свечение и реакция
кнопок на наведение/нажатие. Для пользователей с `prefers-reduced-motion`
анимации автоматически отключаются.

В рабочем пространстве находится компактная инженерная карта мира: четыре
пиктограммы персонажей, три события, причинные связи и разделение
`КАНОН / НОВАЯ СЦЕНА`. Это наглядный MVP будущего графа вселенной. Позже
пиктограммы заменяются кадрами комикса без изменения структуры данных.

Контракт сущностей демо-мира хранится отдельно в `src/entity-contract.js`.
Он содержит восемь синтетических карточек четырёх типов: персонажи, места,
предмет и организация. Стабильные ID, происхождение, уверенность и статус
`DEMO_CANON / DEMO_HYPOTHESIS` проверяются автоматически. Это ручные fixtures,
а не результат извлечения моделью или заимствование из существующей книги.

Добавлена первая ступень фабрики контента: выбранный фрагмент сценария локальная
модель превращает в подробный арт-промпт, после чего облачная встроенная функция
GigaChat `text2image` создаёт иллюстрацию. Пользователь может выделить конкретный
отрывок в редакторе и отправить на иллюстрирование именно его. Результат отображается в редакторе и
скачивается как JPG. Access token вводится пользователем на один сеанс и не
сохраняется в проекте или `localStorage`.

В «Паспортах персонажей» сохраняются имя, профессия/роль, постоянная внешность,
одежда и биография героя. Эти данные автоматически входят в арт-промпт, чтобы
один персонаж сохранял узнаваемость и профессиональные признаки между кадрами.
Каждому персонажу назначается свой цвет. В цветовой карте под редактором все
явные упоминания имени подсвечиваются этим цветом. MVP выделяет точные имена;
распознавание местоимений и скрытых упоминаний честно оставлено следующему уровню.

## Быстрый запуск

Дважды щёлкните:

```text
START_BOOK_STUDIO.cmd
```

Сценарий автоматически:

1. проверяет `llama-server`, модель, Node.js и npm;
2. при первом запуске выполняет `npm install`;
3. запускает MIN/MED/MAX приёмочные тесты;
4. проверяет конфликты портов 1234 и 5173;
5. запускает GigaChat и выполняет короткую контрольную генерацию;
6. запускает Vite и показывает сообщение «BOOK.CRAFT ГОТОВ К ДЕМОНСТРАЦИИ»;
7. открывает `http://127.0.0.1:5173`.

Если проверка не пройдена, окно не закрывается автоматически: показывается
конкретная причина и действие для исправления. Не начинайте запись экрана, пока
не появилось зелёное сообщение о готовности.

Пути уже настроены под текущий компьютер Виктора:

- сервер: `C:\Users\1\.docker\bin\inference\llama-server.exe`;
- модель: `C:\Users\1\.lmstudio\models\bartowski\ai-sage_GigaChat3-10B-A1.8B-GGUF\ai-sage_GigaChat3-10B-A1.8B-Q4_K_S.gguf`.

## Ручной запуск интерфейса

```powershell
npm install
npm run dev
```

Локальный LLM должен отвечать на `http://127.0.0.1:1234`.

## Приёмочные проверки сдаваемого MVP

```powershell
npm test
npm run build
```

`npm test` выполняет три уровня, отдельную проверку контракта сущностей и
интерактивный MIN-UI: настоящий
React-компонент открывает режим книги, выбирает «Триллер» и проверяет изменение
видимого state. Затем MED-UI загружает ограниченное демо, подставляет
контролируемый ответ совместимого локального API, проверяет появление одной
финальной сцены и сохранность ручной правки. MIN также проверяет dropdown/state,
MED — локальную генерацию и ручную редактуру трёх частей, MAX — строгую границу
демо-мира (4 героя, 3 события, ровно 1 генерируемая сцена), отсутствие ранних
RAG/graph-зависимостей и секретов в исходном коде.

Recovery-тест дополнительно подтверждает автосохранение жанра и ручной правки,
видимый статус сохранения и отсутствие API-ключей в сохранённом проекте.

## Что показать на записи экрана

Готовый поминутный сценарий, реплики и приёмочный лист находятся в
[`DEMO_RUNBOOK.md`](DEMO_RUNBOOK.md). Сначала запишите обязательный блок M0,
затем дополнительные функции.

1. Стартовый экран, выбор «Сценарий книги» и кнопка «Загрузить демо».
2. Показать, что загрузились четыре паспорта героев, две части текста и запрос
   на генерацию финальной сцены. Это синтетическая заготовка, не автоматическое
   извлечение из книги.
3. Dropdown «Выберите жанр» с пятью вариантами.
4. Последовательно выбрать «Детектив», «Комедия» и «Триллер».
5. Показать, что подпись «Текущий жанр» меняется сразу.
6. Вернуть «Фантастика» и нажать «Отправить» для генерации финальной сцены.
7. Раскрыть «База знаний произведения», добавить небольшой TXT и выбрать
   «По мотивам» либо «Продолжение».
8. Показать сообщение в чате и обновившиеся блоки «Вступление», «Развитие», «Финал».
9. Вручную изменить текст в одном из блоков.
10. При наличии токена — создать иллюстрацию; это дополнительная, не обязательная часть.
11. Переключиться на стартовый экран и открыть сценарий видеоролика.

Пункты 2–4 непосредственно закрывают формальные требования DZ-6.

## Безопасность

- По умолчанию тексты отправляются только на локальный API.
- При явном запуске AI ART выбранная сцена и арт-промпт передаются в GigaChat API.
- Временный access token хранится только в памяти открытой вкладки.
- Модель и рукописи не добавляются в Git.
- В проекте нет ключей доступа.
- GigaChat не принимает итоговых издательских решений: пользователь может
  вручную изменить каждую часть сценария.
