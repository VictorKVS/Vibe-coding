## Цель

Расширить backend опциональным файлом `audio`. Если текстовый `user_message` отсутствует или содержит только пробелы, backend распознаёт речь и использует расшифровку как обычный пользовательский запрос.

## Матрица требований

| Требование | Реализация | Проверка |
|---|---|---|
| Дополнительное поле `audio` | multipart/form-data, необязательный файл | запрос с аудиофайлом |
| Сохранить прежние поля | `session_id`, `user_message`, `history`, `image` | регрессия текстового запроса |
| STT только при пустом тексте | условие `audio && !user_message.trim()` | голос без текста |
| Получить расшифровку | адаптер STT | текст голосового запроса |
| Использовать как `user_message` | единый pipeline обработки | профиль и история учитываются |
| Текст имеет приоритет | при заполненном тексте STT не вызывается | текст + аудио |
| Безопасная ошибка | понятный ответ без stack trace | ошибка/пустой ответ STT |
| Не хранить секреты | переменные окружения | secret scan |

## Схема

```text
multipart/form-data
 session_id + history + image
 user_message? + audio?
          |
          v
 user_message непустой? ---- да ---> основной pipeline
          |
         нет
          v
 audio присутствует? -------- нет --> валидационная ошибка
          |
         да
          v
 STT adapter -> transcription
          |
          +-- пусто/ошибка --> понятное сообщение пользователю
          |
          v
 user_message = transcription
          |
          v
 основной pipeline без дублирования логики
```

## Минимальные сценарии приёмки

1. Текст без audio работает как раньше.
2. Пустой текст + корректное audio проходит через STT.
3. Текст + audio использует текст и не вызывает STT.
4. Пробелы + audio считаются пустым текстом.
5. Ошибка STT возвращает понятное сообщение.
6. Пустая расшифровка возвращает понятное сообщение.
7. Запрос без текста и без audio отклоняется контролируемо.
8. История, профиль и остальная бизнес-логика применяются к расшифровке.
